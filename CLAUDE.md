# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

Chiclin is a personal finance tracker (gastos/ingresos/ahorros — expenses/income/savings)
that exists as **two independent, parallel implementations** sharing the same data model
and CSV file format:

- **Desktop app** (repo root): Python + PyQt5, packaged as a Windows `.exe`.
- **Android app** (`Android-app/`): Kotlin + Jetpack Compose + Room.

There is no shared code between them — the Kotlin side is a manual, deliberate port of
the Python logic (see `FinanceCalculations.kt` header comment). **When changing a
calculation or business rule in one app, check whether the equivalent needs to change in
the other.** The key correspondences:

| Desktop (Python)              | Android (Kotlin)                              |
|--------------------------------|------------------------------------------------|
| `logic.py: FinanceManager`     | `data/FinanceCalculations.kt` (pure functions) |
| CSV file per month on disk     | Room `entries` table (`data/Entry.kt`)         |
| `app.py` (PyQt5 UI)            | `ui/*Screen.kt` (Compose)                      |

## Desktop app (Python / PyQt5)

### Running

```
python chiclin.py            # GUI (default)
python chiclin.py --cli      # legacy console mode, same FinanceManager backend
```

### Building the .exe

```
pyinstaller --onefile --icon=money_face.ico chiclin.py
```

(`chiclin.spec` is the generated PyInstaller spec; there's also a Nuitka onefile build
config — `chiclin.onefile-build/`, `chiclin.build/` — both are build output, gitignored.)

### Dependencies

No `requirements.txt` exists. Known runtime deps from source: `PyQt5`, `matplotlib`
(with `Qt5Agg` backend), `numpy`. Install what's missing as needed; there is no lockfile
to keep in sync.

### Architecture

Strict separation between business logic and presentation, enforced by convention (see
the docstrings in each file):

- **`logic.py`** — `FinanceManager` class. All state, CSV I/O, and calculations live
  here. No `print()`, no `plt.show()` — it's UI-agnostic and consumed identically by
  both the GUI and CLI. Key behaviors to know before editing:
  - Each entry is stored under key `"{nombre}_{N}"` so the same category name can be
    added multiple times in a month; `_aggregate()` sums by stripping the `_N` suffix
    (`key.rsplit("_", 1)[0]`) when computing totals. This suffix-stripping is
    replicated in the Android CSV importer (`CsvImporter.kt: stripDuplicateSuffix`) —
    keep them consistent if this rule changes.
  - One CSV file per month, named `MM_YYYY.csv` (zero-padded month), stored under
    `chiclin/` next to the executable (`get_base_path()` resolves relative to
    `sys.argv[0]`, which works correctly under both PyInstaller and Nuitka onefile
    builds — don't use `__file__` here).
  - `get_month_filename()` checks for both zero-padded and non-padded legacy filenames
    on disk for backward compatibility before defaulting to the zero-padded form.
  - `switch_month()` saves the currently loaded month before loading a new one —
    callers never need to call `save()` manually around a month switch.
- **`app.py`** — `MainWindow`, the PyQt5 GUI. Two tabs: "Mes actual" (current month:
  add entries, pie chart of gastos, bar chart of ingresos vs gastos) and "Comparación"
  (pick two months, see category-level diffs, plus a recurring-expense breakdown).
  Contains zero business logic — only widget wiring, matplotlib figure drawing, and
  HTML string building for the summary panels.
- **`ui_main.py`** — generated by `pyuic5` from `ui_main.ui`. **Do not hand-edit**;
  regenerate with `pyuic5 ui_main.ui -o ui_main.py` after changing the `.ui` file in Qt
  Designer.
- **`chiclin.py`** — entry point. Also contains the legacy `run_cli()` console mode,
  which duplicates `app.py`'s presentation logic in plain-text/matplotlib-popup form
  but calls the same `FinanceManager` methods.

Matplotlib figures are embedded in `QGraphicsView` widgets via a `QGraphicsScene`
holding a `FigureCanvasQTAgg` (see `_make_canvas`/`_fit_canvas` in `app.py`) — resizing
the window redraws canvases on a debounce timer (`resizeEvent`).

`prev/` holds snapshots of previous built `.exe` versions — historical artifacts, not
something to edit or build from.

## Android app (Kotlin / Jetpack Compose)

Standard Gradle project rooted at `Android-app/`.

### Building / running

```
cd Android-app
./gradlew assembleDebug      # build debug APK
./gradlew test                # unit tests (data/logic layer)
./gradlew connectedAndroidTest # instrumented tests (device/emulator required)
```

Package: `com.example.chiclin`. `minSdk = 24`, `targetSdk = 34`, `compileSdk = 35`.
Kotlin/Java target 11. Uses version catalogs (`gradle/libs.versions.toml`) — add new
dependencies there, not as inline version strings in `build.gradle.kts`.

### Architecture

Standard repository + StateFlow-driven ViewModel pattern:

- **`data/Entry.kt`** — Room `@Entity`, one row per gasto/ingreso/ahorro entry, tagged
  with `mes`/`anio` (no per-month files like the desktop app — everything lives in one
  `entries` table, filtered by month/year in queries).
- **`data/EntriesRepository.kt`** (interface) / **`OfflineEntriesRepository.kt`** (Room
  impl) — the interface exists specifically so a future sync-backed repository can be
  swapped in later without touching the ViewModel; keep new repository-shaped logic
  behind the interface rather than reaching into Room directly from the ViewModel.
- **`data/FinanceCalculations.kt`** — pure, Android-independent port of `logic.py`'s
  calculations (aggregation, month comparison, recurring-expense classification, evolution
  series for charts). Keep it free of Android/UI imports so it stays trivially unit-testable.
- **`data/CsvImporter.kt`** — imports the desktop app's CSV files (`MM_YYYY.csv`,
  `tipo,nombre,valor` rows) into Room, for migrating data from the desktop app to
  Android. Mirrors `logic.py`'s parsing/aggregation rules exactly (see the
  `stripDuplicateSuffix` note above) — this is the main place where the two apps'
  behavior must be kept in sync by hand.
- **`ui/ChiclinViewModel.kt`** — single ViewModel for the whole app; exposes
  `StateFlow`s derived from repository flows via `combine`/`flatMapLatest`/`stateIn`
  (`SharingStarted.WhileSubscribed(5000)` throughout). Drives three screens:
  - `ui/MesActualScreen.kt` — current month, add/delete entries (mirrors desktop tab 1).
  - `ui/ComparacionScreen.kt` — two-month comparison (mirrors desktop tab 2).
  - `ui/HistoricoScreen.kt` — year-scoped trend view across all months; **desktop has
    no direct equivalent** (its CLI-only "comparar todos los meses" and "gastos
    recurrentes" are the closest analogues, folded into this one screen).
  - `ui/components/*Chart.kt` — custom Compose-drawn charts (pie, bar, line) replacing
    matplotlib; `MonthDropdown.kt`/`YearDropdown.kt` are the month/year pickers used
    across screens.

No test files currently exist in either app despite Gradle test tasks being wired up —
there's no existing test suite/pattern to follow yet if you add one.
